# 前端实时火柴人数据接入说明

本文面向使用 FastAPI WebSocket Hub 的前端开发人员，说明相机电脑发送了
什么数据、浏览器实际收到什么消息，以及如何把数据绘制成实时三维火柴人。

通用 WebSocket 控制协议见
[`实时WebSocket接口说明.md`](实时WebSocket接口说明.md)。本文只说明
`avatar.stickman.updated` 业务事件。
如需基于同一条 Halpe26 消息在前端选择显示火柴人或带蒙皮的
Mixamo 假人，见
[`前端Mixamo假人接入说明.md`](前端Mixamo假人接入说明.md)。

## 1. 接入结论

驱动火柴人的 JSON 姿态通道只发送处理完成后的三维骨架，不发送以下内容：

- 不在 JSON 姿态消息中发送 RGB 图像或深度图。
- 不发送二维骨架。
- 不发送 Three.js 网格、火柴人模型或 SMPL 模型。
- 不发送关节旋转角或骨骼四元数。

每条业务消息包含固定 26 项的 Halpe26 三维关节数组。每个有效关节为
`[x, y, z]`，单位是米；无效关节为 JSON `null`。前端使用固定骨骼连接表
连接两个有效关节，即可得到火柴人。

如需同时检查相机实拍、检测框、track ID 和 Halpe26 二维骨架，humanpose 可以再建立一条独立 WebSocket，发送已绘制的 latest-only JPEG 二进制帧。该诊断预览不改变本文的三维骨架协议，详细契约见[《实时 WebSocket 接口说明》](实时WebSocket接口说明.md#10-rgb-实拍--halpe26-骨架预览)。

```text
相机/GPU电脑                         FastAPI电脑/浏览器

RGB-D → 姿态识别 → 26个三维关节 ──WebSocket publish──> Topic Hub
                                                        │
                                                        └──> 前端订阅并绘制

RGB + 检测框 + 二维骨架 ──JPEG binary──> Preview Hub ──> 右上角预览窗
```

当前固定参数：

```text
WebSocket = ws://192.168.30.132:8000/api/realtime/ws
event     = avatar.stickman.updated
topic     = avatar:stickman:FF6690772788
format    = halpe26
```

## 2. 前端建立连接

浏览器可以在连接 URL 中直接订阅火柴人 topic：

```text
ws://192.168.30.132:8000/api/realtime/ws?client_type=browser&client_id=stickman-ui&topics=avatar%3Astickman%3AFF6690772788
```

连接建立后再发送一次 `hello`，便于断线重连后重新声明身份和订阅：

```json
{
  "type": "hello",
  "message_id": "frontend-hello-001",
  "client_type": "browser",
  "client_id": "stickman-ui",
  "topics": ["avatar:stickman:FF6690772788"]
}
```

服务端返回的 `system.welcome`、`system.ack` 和 `system.pong` 都是控制消息，
不能当作骨架数据。只处理同时符合以下条件的消息：

```text
type  = event
event = avatar.stickman.updated
topics 包含 avatar:stickman:FF6690772788
```

如果网页本身通过 HTTPS 打开，浏览器通常会阻止明文 `ws://` 混合内容。
部署环境应改用反向代理提供 `wss://`；当前内网 HTTP 联调可继续使用
`ws://`。

`type=event`。前端应从 `message.payload` 读取骨架，而不是寻找
`message.publish`。

### 3.1 `payload` 字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | number | 当前为 `1`，用于以后兼容协议升级 |
| `keypoint_format` | string | 固定为 `halpe26` |
| `coordinate_system` | object | 坐标系、单位、向上轴和地面定义 |
| `source_id` | string | 相机业务标识，当前为 `FF6690772788` |
| `frame_number` | number | 本次相机进程中的递增帧号；允许跳号，进程重启后可重新从 0 开始 |
| `timestamp_ms` | number | 相机帧时间，毫秒整数，可安全存入 JavaScript `Number` |
| `status` | string | 当前人物/深度状态，见第 7 节 |
| `joints` | array | 固定 26 项；每项是米制 `[x,y,z]` 或 `null` |

当前协议不包含置信度、速度、角度或骨长。前端不得假设这些字段存在。

## 5. 火柴人骨骼连接

以下 25 条连接与相机端使用的 `HALPE26_LINKS` 完全一致：

```js
export const HALPE26_LINKS = [
  [15, 13], [13, 11], [11, 19],
  [16, 14], [14, 12], [12, 19],
  [17, 18], [18, 19],
  [18, 5], [5, 7], [7, 9],
  [18, 6], [6, 8], [8, 10],
  [1, 2], [0, 1], [0, 2], [1, 3], [2, 4],
  [15, 20], [15, 22], [15, 24],
  [16, 21], [16, 23], [16, 25]
];
```

绘制规则：

1. `joints[i] !== null` 时显示第 `i` 个关节点。
2. 一条连接 `[a,b]` 只有在 `joints[a]` 和 `joints[b]` 都不是 `null`
   时才显示。
3. 任何 `null` 都必须跳过，不能转换为 `[0,0,0]`，否则会出现连向原点
   的错误骨骼。
4. 数据已经在相机端完成时序滤波和骨长约束，前端通常不需要再次做重度
   平滑。可只对显示位置做轻量插值。

相机当前最多产生约 15 帧/秒。发送端采用 latest-only 策略，网络慢时会
主动覆盖尚未发送的旧姿态，因此 `frame_number` 跳号是正常行为。前端也
应优先显示最新帧，不要为补齐帧号而建立不断增长的队列。

## 6. 坐标系与 Three.js 转换

发送坐标具有以下约定：

```text
右手坐标系
单位：米
向上轴：+Z
地面：Z = 0
```

如果前端三维场景本身也是 Z-up，可以直接使用 `[x,y,z]`。Three.js 默认
使用 Y-up，因此推荐用以下右手系旋转：

```js
import * as THREE from "three";

export function applicationToThree(joint) {
  const [x, y, z] = joint;
  return new THREE.Vector3(x, z, -y);
}
```

转换后：

- 应用坐标 `+Z` 变为 Three.js `+Y`。
- 应用坐标地面 `Z=0` 变为 Three.js 地面 `Y=0`。
- 仍然保持右手坐标系。
- 数据单位继续是米；若前端场景以厘米为单位，再统一乘以 100。

不要根据屏幕显示效果单独交换人物左右关节。需要整体调整朝向时，应旋转
整个火柴人根节点，而不是修改 Halpe26 索引。

## 7. `status` 的处理建议

| `status` | 含义 | 前端建议 |
| --- | --- | --- |
| `ok` | 人物通过完整性检查并完成三维恢复 | 正常绘制所有非 `null` 关节 |
| `no_person` | 当前帧没有检测到人物 | 短时可显示仍非 `null` 的预测关节；持续无数据则隐藏 |
| `no_valid_3d_joints` | 检测到人物，但当前没有有效深度关节 | 跳过 `null`；没有有效关节时隐藏 |
| `partial_person_out_of_frame` | 人物被画面边缘截断，轨迹已终止 | 立即隐藏或淡出旧火柴人 |
| `awaiting_full_reentry` | 等待人物完整回到画面后重新建轨 | 保持隐藏，不要无限保留旧姿态 |

最终是否能绘制，应以 `joints` 中是否存在非 `null` 项为准，不能只检查
`status === "ok"`。相机端的短时预测可能在 `no_person` 时仍提供少量可用
关节。

建议以前端接收时间判断“数据是否过期”，例如 300～500 ms 没收到新帧
就隐藏火柴人。除非两台电脑已做可靠时钟同步，不建议直接用
`Date.now() - timestamp_ms` 判断网络延迟。

## 8. 可直接使用的浏览器接收代码

下面的代码完成连接、重连、消息过滤、结构检查和 latest-only 缓存。
渲染循环始终读取最新姿态，不逐帧堆积消息。

```js
const TOPIC = "avatar:stickman:FF6690772788";
const WS_BASE = "ws://192.168.30.132:8000/api/realtime/ws";
const CLIENT_ID = "stickman-ui";

let socket = null;
let reconnectTimer = null;
let reconnectDelayMs = 500;
let latestPose = null;
let latestArrivalMs = 0;

function isJoint(value) {
  return value === null || (
    Array.isArray(value) &&
    value.length === 3 &&
    value.every(Number.isFinite)
  );
}

function isStickmanPayload(value) {
  return value !== null &&
    typeof value === "object" &&
    value.schema_version === 1 &&
    value.keypoint_format === "halpe26" &&
    Number.isInteger(value.frame_number) &&
    Number.isFinite(value.timestamp_ms) &&
    typeof value.status === "string" &&
    Array.isArray(value.joints) &&
    value.joints.length === 26 &&
    value.joints.every(isJoint);
}

function connectStickman() {
  const query = new URLSearchParams({
    client_type: "browser",
    client_id: CLIENT_ID,
    topics: TOPIC
  });
  socket = new WebSocket(`${WS_BASE}?${query}`);

  socket.addEventListener("open", () => {
    reconnectDelayMs = 500;
    const messageId = globalThis.crypto?.randomUUID?.() ??
      `frontend-hello-${Date.now()}-${Math.random()}`;
    socket.send(JSON.stringify({
      type: "hello",
      message_id: messageId,
      client_type: "browser",
      client_id: CLIENT_ID,
      topics: [TOPIC]
    }));
  });

  socket.addEventListener("message", (event) => {
    let message;
    try {
      message = JSON.parse(event.data);
    } catch {
      return;
    }

    if (
      message.type !== "event" ||
      message.event !== "avatar.stickman.updated" ||
      !Array.isArray(message.topics) ||
      !message.topics.includes(TOPIC) ||
      !isStickmanPayload(message.payload)
    ) {
      return;
    }

    // 只保留最新一帧。frame_number 在相机进程重启后可以重新从 0 开始，
    // 因此不要永久丢弃 frame_number 小于上一进程的消息。
    latestPose = message.payload;
    latestArrivalMs = performance.now();
  });

  socket.addEventListener("close", () => {
    clearTimeout(reconnectTimer);
    reconnectTimer = setTimeout(connectStickman, reconnectDelayMs);
    reconnectDelayMs = Math.min(reconnectDelayMs * 2, 10000);
  });

  socket.addEventListener("error", () => {
    socket.close();
  });
}

connectStickman();

function animationFrame() {
  const stale = performance.now() - latestArrivalMs > 500;
  if (latestPose && !stale) {
    renderStickman(latestPose);
  } else {
    hideStickman();
  }
  requestAnimationFrame(animationFrame);
}

requestAnimationFrame(animationFrame);
```

`renderStickman()` 和 `hideStickman()` 是前端项目自己的渲染函数。下一节
给出 Three.js 的核心实现。

## 9. Three.js 火柴人核心示例

以下示例预先创建 26 个关节球和 25 条线，每帧只更新坐标和可见性，避免
不断创建对象造成垃圾回收抖动。

```js
import * as THREE from "three";
import { HALPE26_LINKS } from "./halpe26";

const stickman = new THREE.Group();
scene.add(stickman);

const jointGeometry = new THREE.SphereGeometry(0.025, 10, 8);
const jointMaterial = new THREE.MeshBasicMaterial({ color: 0x101010 });
const boneMaterial = new THREE.LineBasicMaterial({ color: 0x101010 });

const jointMeshes = Array.from({ length: 26 }, () => {
  const mesh = new THREE.Mesh(jointGeometry, jointMaterial);
  mesh.visible = false;
  stickman.add(mesh);
  return mesh;
});

const boneLines = HALPE26_LINKS.map(([start, end]) => {
  const positions = new Float32Array(6);
  const geometry = new THREE.BufferGeometry();
  geometry.setAttribute(
    "position",
    new THREE.BufferAttribute(positions, 3)
  );
  const line = new THREE.Line(geometry, boneMaterial);
  line.frustumCulled = false;
  line.visible = false;
  stickman.add(line);
  return { start, end, line };
});

function toThree(joint) {
  return new THREE.Vector3(joint[0], joint[2], -joint[1]);
}

export function renderStickman(payload) {
  const points = payload.joints.map((joint) =>
    joint === null ? null : toThree(joint)
  );

  points.forEach((point, index) => {
    jointMeshes[index].visible = point !== null;
    if (point !== null) {
      jointMeshes[index].position.copy(point);
    }
  });

  for (const { start, end, line } of boneLines) {
    const a = points[start];
    const b = points[end];
    line.visible = a !== null && b !== null;
    if (!line.visible) continue;

    const position = line.geometry.attributes.position;
    position.setXYZ(0, a.x, a.y, a.z);
    position.setXYZ(1, b.x, b.y, b.z);
    position.needsUpdate = true;
  }
}

export function hideStickman() {
  jointMeshes.forEach((mesh) => { mesh.visible = false; });
  boneLines.forEach(({ line }) => { line.visible = false; });
}
```

如果需要更粗的骨骼，不要依赖 `LineBasicMaterial.linewidth`，因为多数浏览器
和 WebGL 平台只支持 1 像素线宽。可以把每条连接改成圆柱体，并根据两个
端点计算圆柱体的中心、长度和旋转。

## 11. 联调检查

相机电脑启动命令：

```bash
cd /home/fr1511b/program/workspace/humanpose
conda activate rgbd-avatar

PYTHONPATH=src python scripts/view_live_mannequin.py \
  --source sdk \
  --device cuda:0 \
  --recovery-method pointcloud_cluster \
  --headless
```

前端没有收到骨架时，依次检查：

1. 浏览器 WebSocket 是否连接到 `192.168.30.132:8000`。
2. 是否订阅了完整 topic `avatar:stickman:FF6690772788`。
3. 是否过滤 `type=event`，而不是错误等待 `type=publish`。
4. 相机端是否出现 `Stickman WebSocket connected`。
5. 相机端统计中的 `sent_frame_count` 是否增长。
6. `publish_ack_count` 增长但 FastAPI ACK 的 `published_to=0` 时，通常表示
   当时没有任何前端连接订阅该 topic。
7. 收到消息但没有显示时，检查 `status` 和 `joints` 是否全部为 `null`；
   `partial_person_out_of_frame` 表示人物需要完整回到相机画面。
8. FastAPI 当前为进程内 Hub，应使用单 worker；多个 worker 之间不会自动
   共享 WebSocket 订阅状态，除非后续接入 Redis/Kafka 等共享 broker。

当前链路已经用真实相机数据完成 `sent=5, ack=5` 联调。
